# System Analysis

## Purpose

Analyze how users, system components, features, and business processes interact.

## When to Use

Use this skill when:

* Designing use cases.
* Designing user flows.
* Analyzing business processes.
* Defining system modules.
* Preparing system architecture.

## Responsibilities

The agent must identify:

* Actors
* Use cases
* User flows
* Business processes
* System boundaries
* Module responsibilities
* Dependencies
* State transitions
* Business rules

## Rules

* Each actor must have clearly defined responsibilities.
* Each module must have a clear responsibility.
* Avoid unnecessary coupling between modules.
* Keep business logic explicit.
* Do not duplicate responsibilities across modules.
* Preserve consistency between user flows and requirements.

## Workflow

1. Identify actors.
2. Identify goals for each actor.
3. Map actor-to-system interactions.
4. Define use cases.
5. Define primary and alternative flows.
6. Identify business rules.
7. Identify module boundaries.
8. Identify dependencies.
9. Validate the model against project requirements.

## Output

Depending on the task, produce:

* Actor model
* Use case model
* User flow
* System flow
* Module responsibilities
* Business rules
* State transitions
* Dependency analysis

## Restrictions

Do not:

* Design database schemas during pure system analysis.
* Choose frameworks without technical requirements.
* Add functionality not supported by the project requirements.
