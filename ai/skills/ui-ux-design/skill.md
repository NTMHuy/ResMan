# UI/UX Design

## Purpose

Design user interfaces and experiences that are appropriate for the user's role, device, context, and task.

## When to Use

Use this skill when:

* Designing new screens.
* Designing user flows.
* Reviewing UI/UX.
* Creating responsive interfaces.
* Designing role-specific interfaces.

## Core Principle

UI decisions must be driven by:

1. User role
2. User goal
3. User workflow
4. Device
5. Usage context
6. Task priority

Do not design the same interface for every role simply because the underlying system is shared.

## Responsibilities

The agent must consider:

* Information hierarchy
* Navigation
* Interaction patterns
* Responsive behavior
* Accessibility
* Feedback states
* Loading states
* Empty states
* Error states
* Confirmation states
* Role-specific workflows
* Device-specific interaction

## Rules

* Design from user tasks rather than database structure.
* Prioritize frequently used actions.
* Minimize unnecessary interactions.
* Keep terminology consistent with the product.
* Do not introduce UI functionality that is not supported by the requirements.
* Design mobile, tablet, and desktop experiences according to their usage context.
* Maintain consistent design language across the product.

## ResMan Context

When designing ResMan interfaces, consider the differences between:

* Customer using a restaurant tablet.
* Staff using a mobile phone.
* Kitchen staff using a desktop display.
* Cashier using a desktop system.
* Warehouse staff using a desktop system.
* Manager using a desktop system.

The same business capability may require different interfaces for different roles and devices.

## Workflow

1. Identify the target actor.
2. Identify the actor's goal.
3. Identify the device.
4. Identify the task frequency and priority.
5. Design information hierarchy.
6. Design navigation and interaction.
7. Define important UI states.
8. Check responsive behavior.
9. Validate the flow against requirements.

## Output

Depending on the task, provide:

* Screen structure
* User flow
* Navigation structure
* Component hierarchy
* Interaction behavior
* Responsive behavior
* UI states
* UX considerations

## Restrictions

Do not:

* Design screens based only on database tables.
* Assume all users share the same interface.
* Add unnecessary visual complexity.
* Prioritize visual appearance over usability.
* Modify product requirements through UI design.
