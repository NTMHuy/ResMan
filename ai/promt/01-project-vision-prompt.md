# Project Vision Generation Prompt

## Role

You are a Senior Product Analyst and Project Manager.

Your task is to analyze a software project idea and create a clear and realistic Project Vision.

You are responsible for analyzing the project from a business and user perspective.

Do NOT focus on programming languages, frameworks, database technologies, APIs, or implementation details unless they are necessary to understand the project.

---

## Project Idea

The project is a:

**Restaurant Management System**

The system is intended to manage the main activities of a restaurant and connect different roles involved in the restaurant's operation.

The main user roles currently identified are:

* Customer
* Order Staff
* Manager
* Warehouse Staff
* Kitchen Staff

The project is intended to become a complete system that can support restaurant operations from ordering food to kitchen processing, inventory management, management, and reporting.

The project will also apply AI during the software development process.

AI will be used to support activities such as:

* Requirement analysis
* User flow analysis
* Use case analysis
* System modeling
* Feature decomposition
* Project planning
* Task generation
* Development assistance
* Review and validation

After the core system is completed, an AI-powered food recommendation feature may be added to recommend dishes to customers based on their previous orders and behavior.

---

## Main Objective

Analyze the project idea above and create a Project Vision that can be used as the foundation for the next stages of system development.

The Project Vision must provide a clear understanding of:

1. What problem the project solves
2. Why the project should be built
3. Who will use the system
4. What the system is expected to provide
5. What is included in the project
6. What is outside the current scope
7. How AI contributes to the project
8. What the expected final product looks like

---

## Analysis Requirements

### 1. Problem

Identify the main problems that restaurants may face when managing operations manually or using disconnected systems.

Focus on problems related to:

* Customer ordering
* Order processing
* Kitchen coordination
* Inventory management
* Employee management
* Restaurant management
* Reporting
* Information synchronization

Do not invent highly specialized problems without a reasonable basis.

---

### 2. Project Goal

Define the main goal of the system.

The goal should describe the business value and expected improvement rather than technical implementation.

---

### 3. Target Users

Analyze the five identified roles:

* Customer
* Order Staff
* Manager
* Warehouse Staff
* Kitchen Staff

For each role, describe:

* Who they are
* What they need from the system
* What problems the system helps them solve

Do not define detailed features yet.

---

### 4. Project Scope

Define the project's scope at a high level.

Separate the scope into:

#### In Scope

Functions and areas that should belong to the core restaurant management system.

#### Out of Scope

Functions that are not necessary for the first complete version of the project.

The scope should be realistic for a student software project.

Do not continuously expand the system.

---

### 5. Core System Areas

Identify the major functional areas of the system.

For example:

* Customer Management
* Employee Management
* Menu Management
* Order Management
* Kitchen Management
* Inventory Management
* Payment
* Review
* Reporting

You may add or remove areas if your analysis determines that they are necessary or unnecessary.

Explain briefly why each area belongs to the system.

---

### 6. AI Role

Clearly distinguish between two different uses of AI.

#### AI as a Development Assistant

Explain how AI can participate in the software development lifecycle:

Idea
→ Requirement Analysis
→ User Analysis
→ User Flow
→ Use Case
→ Modeling
→ Planning
→ Task Generation
→ Development
→ Review

#### AI as a Product Feature

Explain the potential AI-powered feature inside the restaurant system.

The initial idea is:

**Food Recommendation**

The system may analyze a customer's previous orders and recommend suitable dishes.

Do not design the machine learning model yet.

---

### 7. Expected Outcome

Describe what the final project should provide from the user's perspective.

Focus on the completed product rather than implementation technology.

---

### 8. Assumptions and Uncertainties

Identify information that has not yet been decided.

For example:

* Restaurant size
* Number of branches
* Payment methods
* Whether table management is required
* Whether delivery is included
* Whether customers need an account
* Whether the system supports multiple restaurants

Do not make arbitrary decisions.

List these as assumptions or questions that can be resolved in later analysis stages.

---

## Important Rules

1. Do not write source code.
2. Do not design the database.
3. Do not design APIs.
4. Do not select frameworks or programming languages.
5. Do not create detailed UI designs.
6. Do not create detailed use cases yet.
7. Do not create detailed user flows yet.
8. Do not add unnecessary features.
9. Keep the project realistic and manageable.
10. Clearly distinguish confirmed information from assumptions.
11. Maintain consistency with the five identified user roles.
12. The output must be suitable for saving as a project documentation file.

---

## Output Format

Generate the final result using the following Markdown structure:

# Project Vision

## 2. Problem Statement

## 4. Target Users

### 4.1 Customer

### 5.2 Out of Scope

## 6. Core System Areas

## 7. AI in the Development Process

## 8. AI Features in the Product

## 9. Expected Outcome

## 10. Assumptions and Open Questions

---

## Quality Check

Before producing the final answer, verify that:

* The project has a clear purpose.
* The problem and goal are consistent.
* All five user roles are covered.
* The scope is realistic.
* AI's role in development is clearly explained.
* AI product features are separated from AI development assistance.
* No unnecessary technical implementation details are included.
* No major assumptions are presented as confirmed facts.

Return only the completed Project Vision document.
